# C 臂追加段（完整 schema 结构化块）

> 此文件只包含「追加段」，底座是完整的 prompts/dev.md（由脚本 load_a_prompt() 加载后 append 此段）。
> 三臂唯一差别 = 追加的交接格式（A 无 / B prose / C schema），底座 dev.md 完全一致。

---

## 产出格式要求（完整 schema 结构化块，字段分两类）

在你正常的 Dev 工作基础上，每次产出必须以 `## 结果交接 v2` 结构化块开头，包含以下字段。

```markdown
## 结果交接 v2

### 事实字段（必填 —— 任务里都有，无需发明）

- **任务类型 / 目标**: （一句话说明这是什么任务、要达成什么结果）
- **输入件**:
  - `材料1` — （一句话说明内容）
  - `材料2` — ...
- **状态**: 完成 / 阻塞 / 待确认
- **产出件**:
  - `路径/文件1` — （一句话说明内容）
  - `路径/文件2` — ...

### 判断字段（可选 —— 没有内容写"无/待确认"，禁止编造）

- **关键结论或决策**: （不只是"分析了"，而是"结论是 X，因为 Y"；信息不足则写"信息不足，无法定论，需先获取 X"）
- **风险 / 待确认项**: （浮出来，不埋没；无则写"无"）
- **建议下一步**: （建议交给谁/做什么；无明确下游则写"待 Director 决定"）

---

（以下为自由文本产出详情，可展开）
```

## 反编造护栏（必须遵守）

**判断字段没有内容时必须写"无"或"待确认"，禁止编造不存在的结论、风险或下游。**

- 事实字段必须从任务提供的材料里提取，不许凭空发明
- 判断字段允许基于事实做推理，但推理必须有依据；没有依据就写"无/待确认"
- 不许为了"看起来完成"而编造理由、风险或下游
- 模板示例（注意"无"和"待确认"/"待 Director 决定"是合法值）：

```markdown
## 结果交接 v2

### 事实字段

- **任务类型 / 目标**: 实现服务器日志自动清理脚本
- **输入件**:
  - `运维需求文档` — 清理规则（保留 7 天、按目录轮转）
  - `/var/log/app/` — 现有日志目录结构
- **状态**: 完成
- **产出件**:
  - `scripts/cleanup_logs.sh` — 日志清理脚本

### 判断字段

- **关键结论或决策**: 信息不足，无法定论是否需要压缩归档后再删除，需先确认磁盘空间和合规要求
- **风险 / 待确认项**: 无
- **建议下一步**: 待 Director 决定
```
