# Advisor Prompt 精简基准测试

> 目标：验证 Advisor prompt 中"波特五力/SWOT/决策矩阵"三个教科书框架的精简是否导致弱模型（SenseNova）质量下降。
> 方法论：原版 vs 删减版，各跑 N=3 次，人工盲评配对打分，任务完成度权重最高（50%）。
> **本次结论：全砍版未通过（94.8% < 95%），最终只砍决策矩阵一节（-28 行），波特五力+SWOT 保留，已于 8c8e8c4 回填 prompts/advisor.md。**

| 任务 | 原版 | 全砍版 | 差距 | 赢家 |

### 最终执行：选择性精简

基于以上数据，只砍决策矩阵一节（任务2显示噪音级差距，可砍），波特五力+SWOT 保留（任务1裂口 0.87，决定性信号）。

- **决策矩阵**：从 34 行精简到 6 行（保留分步骨架+敏感性分析+关键提问，砍掉示例表/注意事项散文/重复提问清单）
- **波特五力、SWOT**：原样保留
- **净减**：~28 行（源文件），五运行时产物同步重新生成
- **回填 commit**：8c8e8c4

### 关键发现：结构脚手架机制

详细框架的分步骨架对弱模型起"结构脚手架"作用——骨架被砍后，弱模型会即兴自造子表、过度展开、撞到输出长度上限导致来不及下结论（见全砍版任务一输出：波特五力铺成 5 张子表，写到财务模型时被截断，根本没到"给建议"那一步）。

**精简原则：可砍提问清单/案例/散文，保留框架的分步骨架。**

## 使用方法

### 第 1 步：跑原版测试

```bash
# SenseNova 配置从 opencode.json 的 jensen003/souljian03 provider 读取
# 或设置环境变量 SENSENOVA_API_KEY / SENSENOVA_MODEL
python3 benchmark/run_advisor_benchmark.py --variant original --runs 3
```

### 第 2 步：跑删减版测试

```bash
python3 benchmark/run_advisor_benchmark.py --variant trimmed --runs 3
```

### 第 3 步：人工盲评配对打分

本次用人工盲评（Dia 按 rubric.md 打分，不告知哪个是原版/删减版）。
输出格式：每道题先贴题目，然后"变体甲""变体乙"各自的 N 次输出，甲/乙随机打乱。
打分完成后揭晓对应关系，汇总分析。

## 判定规则

- 删减版总分 ≥ 原版总分的 95% → 质量不降，可考虑删减
- 删减版总分 < 原版总分的 95% → 质量下降，保留原版
- 结论存疑（分数接近、方差大）→ 默认保留原版

## 方法论铁律

1. **先跑基线存分**：原版先跑，分数存底
2. **harness 冻结后再动刀**：测试框架稳定后才改 prompt
3. **每变体跑 N=3-5 次比分布**：不看单次（弱模型有温度，单次可能被噪声带偏）
4. **裁判盲评+配对**：不告诉裁判哪个是原版/删减版，A/B 放同一次直接对比
5. **结论存疑默认保留**：宁可保留冗余，不冒质量下降的风险
6. **精简后对"实际发布版"再跑一次基准确认**：不能只凭"全砍版 vs 原版"的结论推断"选择性精简版"的质量——砍的组合不同，结果可能不同。本次选择性精简（只砍决策矩阵）未单独重跑基准，属基于数据的推断，后续若对其他角色做类似精简，应把"精简后再跑一次"作为标准流程。

## 结构化通信实验（已评估 · 不采纳）

> **结论：维持现状自由交接，不引入结构化交接格式。** 详见 [docs/design-structured-comms.md](../docs/design-structured-comms.md)。

实验：A（现状自由）/ B（prose 强制）/ C（结构化块）三臂对比，三臂共享完整 `prompts/dev.md` 底座，唯一差别 = 追加的交接格式。3 个真实任务 × 3 臂 × 2 次 = 18 次，SenseNova 6.7-flash-lite，盲评。

结果：三臂 0 编造、信息完整性打平（task2/task3），task1 差距系无工具环境 confound。B/C 为加复杂度改动，未明显超过 A → 维持 A。
